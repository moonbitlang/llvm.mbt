# Q-03. 字符串边界重构的改动与审核范围 已解决

> 最后更新日期：2026-08-03
> 仓库：github.com/moonbitlang/llvm.mbt
> 记录者：Codex-GPT-5

## 问题描述

此前被 reset 的一组提交在短时间内同时处理字符串边界、UTF codec、LLVM operation error、nullable、byte span、高层 workflow 等问题，用户难以确认每段代码的来由和正确性。当前仓库的后续改动必须保持用户能够理解和审核，字符串边界应作为当前唯一议题独立完成。

2. [Q-02. C 输出字符串的复制与释放责任](Q-02-output-string-boundary.md)（实施约束）

## 建议的解决方案

### A1. 单一议题、小步讨论和审核 【建议采纳】

#### 方案描述

当前只讨论和处理字符串边界。输入表示、输出 ownership、UTF‑8转换及对应测试需要在实施前说明并由用户审核；不在同一批改动中顺带处理 LLVM operation error、nullable、MemoryBuffer、enum 或高层资源管理。后续议题在字符串边界完成后再分别讨论。

#### 优点

- 每段代码都能对应到一个已经讨论过的问题和明确的边界条件。
- review 可以验证局部不变量，不必一次理解多个相互影响的重构。
- 如果某一步判断需要修正，可以局部撤回，不会连带推翻大量无关工作。

#### 缺点

- 完成整个生产化工作的总提交数会增加。
- 迁移期间新旧字符串边界可能短暂并存，需要明确标识和测试，避免误以为迁移已经完成。

## 最终采用方案

A1. 单一议题、小步讨论和审核
